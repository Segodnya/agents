# chore-agent-cli

Находим в транскриптах повторы, которые агент делает руками, и превращаем их в подкоманду `agent-cli` или правило мода `agent-cli-first`. Считает скрипт, решаешь ты: каждый **сигнал** получает **вердикт** и **слой**.

## Слои

**Слой** — где живут CLI и мод. Их два, оба могут стоять одновременно:

| Слой      | CLI                     | Мод                                       | Транскрипты               | Что туда идёт                                       |
| --------- | ----------------------- | ----------------------------------------- | ------------------------- | --------------------------------------------------- |
| `user`    | `~/.claude/bin/agent-cli` | `~/.claude/skills/agent-cli-first/`       | все проекты               | повторы в ≥2 проектах: git-состояние, трекеры, CI   |
| `project` | `<repo>/bin/agent-cli`  | `<repo>/.claude/skills/agent-cli-first/`  | только текущий репозиторий | знание этого репо: его проверки, скрипты, конфиги   |

`~/.claude` — это `$CLAUDE_CONFIG_DIR`, если он задан. Слой берётся из аргумента вызова (`user` / `project`); без аргумента — `project` в git-репозитории, иначе `user`. Назови выбранный слой в отчёте.

`SKILL_DIR` — путь из строки `Base directory for this skill:`.

## Контракт

Скан читает CLI и мод только через этот контракт, держи его в обоих слоях:

- `agent-cli help --json` печатает объект, ключи которого — имена подкоманд.
- Упавший вызов печатает строку `error: …` и выходит с кодом 1.
- Мод экспортирует `register` из `hooks/register.ts`; отказ на Bash начинается с `agent-cli-first: use \`<путь к CLI> <подкоманда>`.
- `AGENT_CLI_RAW=1` в команде пропускает её мимо мода.

## 0. Если CLI в слое нет

Скан работает и без CLI и мода: тогда всё в `repeatedRaw`/`repeatedReads` — кандидаты. Собери первую версию из них:

1. CLI — один исполняемый файл без новых зависимостей. В `project` — на рантайме репо, в `user` — на `bun` или `node`. Каждая подкоманда — запись `cmds.<имя> = { summary, help, flags, run }`; у всех `--help` и `--json`, вывод — итог и ошибки, без логов.
2. Первые подкоманды — из скана. Обычно в `user`: состояние (ветка, статус, дифф, последние коммиты), трекер и CI. Обычно в `project`: проверки (типы, линт, юнит, e2e) и справка о проекте (скрипты, цели make, хуки).
3. Факты подкоманда читает при вызове: `user` — из git и окружения текущего каталога, `project` — из файлов репо (`package.json`, `Makefile`, `tsconfig.json`). Так CLI не устаревает. Бинари CLI зовёт так, как требует `CLAUDE.md` своего слоя.
4. Мод — через скилл `plugin-authoring`, в папку мода из таблицы: `.claude-plugin/plugin.json`, `hooks/hooks.json`, `hooks/register.ts`. `SECTION` идёт в системный промпт и в промпт субагента. В `SECTION` и в отказах — путь к CLI своего слоя. Для `project` добавь в `.gitignore` `.claude/skills/*/.claude-plugin/types/` и `.claude/skills/*/tsconfig.json`: их пишет движок.

Дальше — шаги 1–4 как обычно.

## 1. Скан

```sh
bun "SKILL_DIR/scan.ts" --scope <слой> --days 7
```

Запускай из каталога внутри репо. `--min-sessions N` — порог повтора (по умолчанию 3), `--min-projects N` — порог разброса для `user` (по умолчанию 2), `--json` — для разбора кодом.

Скрипт отсекает команды, которые перенаправляют моды слоя: в `project` — оба мода, в `user` — только пользовательский. Счёт идёт по сессиям, не по вызовам: повтор в одной сессии — привычка задачи, повтор в трёх — кандидат. В `user` строки ранжирует разброс по проектам (колонка `p`).

## 2. Вердикты

Секции отчёта — от сильного сигнала к слабому:

| Секция          | Что значит                                                                | Типичный вердикт                                                                                |
| --------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `rawBypass`     | агент обошёл мод через `AGENT_CLI_RAW=1`: CLI не выразил вызов            | флаг или подкоманда, которая выражает этот вызов                                                |
| `cliErrors`     | вызов `agent-cli` упал (`error: …`)                                       | починить флаг или `--help`, по которому агент ошибся                                            |
| `repeatedRaw`   | сырая команда выше порога, мод её не ловит                                | подкоманда — если вывод нужен агенту; правило мода — если подкоманда уже есть                   |
| `repeatedReads` | файл читают через Read выше порога                                        | факт в `info`/`ctx`, если это поиск по конфигу; иначе пропуск                                   |
| `denied`        | мод перенаправил вызов                                                    | много на одну подкоманду → агент не видит секцию про agent-cli: правь `SECTION` в `register.ts` |
| `cliUse`        | какие подкоманды реально зовут; `unknown:*` — опечатки и выдуманные имена | подкоманда без вызовов несколько недель подряд → кандидат на удаление                           |

Вердикт — один из: **подкоманда**, **флаг**, **правило мода**, **удалить**, **пропуск** (с причиной). Пропуск — правки и одноразовые скрипты (`sed -i`, `cat >`, `python3 -`, `python3 -c`, `mkdir`, `rm`), команды без устойчивой формы и всё, где мод отнял бы у агента нужный вывод.

Слой вердикта — по сути команды, а не по скану, которым её нашёл. Команда без знания репо (`git branch --show-current`, `jira issue view`) — в `user`, даже если всплыла в `project`-скане. Команда со знанием репо (его скрипт, его пути, его цель make) — в `project` этого репо, даже если всплыла в `user`-скане; тогда назови репо из сэмплов.

Шаг закончен, когда вердикт и слой есть у каждой строки `rawBypass` и `cliErrors` и у каждой строки `repeatedRaw`/`repeatedReads` выше порога.

## 3. Отчёт и аппрув

Таблица пользователю: сигнал (секция, ключ, проекты/сессии/вызовы, один пример) → вердикт → слой → что меняется (имя подкоманды и флаги или регэксп правила). Правки — только по аппруву.

## 4. Правка

Одна подкоманда живёт в трёх местах своего слоя, правь все три в одной правке:

1. CLI: запись `cmds.<имя>` с `summary` (из него собирается `--help`), `help` и `flags`.
2. `register.ts`: строка в `RULES`, которая отправляет сырую команду на подкоманду.
3. `register.ts`: имя подкоманды в `SECTION`.

Подкоманда переезжает между слоями — убери её из старого слоя в той же правке.

Проверка — каждая принятая правка:

- новая подкоманда отработала один раз на реальном репо, с `--json` и без; для `user` — в двух разных репо;
- повторный скан того же слоя: семейство из `repeatedRaw`, которое закрыла правка, ушло из отчёта (мод теперь его ловит).

Мод перечитывает `register.ts` в конце хода: до него новое правило не действует, а ложный отказ старого правила обходится через `AGENT_CLI_RAW=1`.
