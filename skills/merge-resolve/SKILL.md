# merge-resolve — разрешение конфликтов git

Порядок: **намерение коммитов → структурная сверка → план → аппрув → правки → верификация**.

Не делай `git add` / `git commit`. Исключение — конфликт delete/modify: он резолвится только через `git rm <file>` или `git add <file>`; сделай и напиши в отчёте, что тронул индекс.

Не запускай `build`.

## Шаг 0 — тип операции

| Операция    | ours (`:2`)                         | theirs (`:3`)                  |
|-------------|-------------------------------------|--------------------------------|
| merge       | HEAD — твоя ветка                   | вливаемая ветка (`MERGE_HEAD`) |
| rebase      | ветка-**цель** — ИНВЕРТИРОВАНО      | **твой** коммит                |
| cherry-pick | текущая ветка                       | переносимый коммит             |
| stash pop   | текущее состояние ветки             | содержимое из stash            |

Определяется по `.git/`: `MERGE_HEAD` → merge, `rebase-merge`/`rebase-apply` → rebase, `CHERRY_PICK_HEAD` → cherry-pick. Скрипт Шага 1 печатает это сам. **При rebase стороны инвертированы** — частый источник ошибки.

## Шаг 1 — собрать контекст

```bash
bash <skill_dir>/scripts/gather_conflicts.sh
```

Печатает тип операции, unmerged-файлы, конфликтные маркеры с номерами строк, коммиты обеих сторон и объединённый `git diff`. Полные версии сторон: `git show :1:<file>` (base), `:2:` (ours), `:3:` (theirs).

## Шаг 1.5 — структурная сверка (до разбора маркеров)

```bash
python3 <skill_dir>/scripts/check_merge_symbols.py
```

Ловит то, что лежит **вне маркеров** и не видно ни tsc, ни eslint, ни jest: `ДУБЛЬ` (авто-мерж вставил вторую копию метода — вторая затирает первую) и `ПРОПАЛ` (сторона переименовала метод, удаление уехало в неконфликтную зону). Работает и на конфликтном мерже, и на закоммиченном авто-мерже.

Скрипт — регекс-эвристика, вердикт выносишь ты:

- `.ts`/`.tsx` — подтверди через `LSP documentSymbol` (дубль) и `findReferences` (кто остался с вызовом). Сначала `ToolSearch("select:LSP")`.
- легаси-Backbone, `.php`, `.js` без типов — LSP не поможет, читай исходник обеих сторон.

Дубль может быть перегрузкой, пропажа — намеренным удалением. Каждый пункт отчёта объясни в плане (Шаг 4).

Отдельно проверь файлы, пришедшие одной стороной целиком (`git diff --name-only <base>..theirs` против ours) — в первую очередь тесты и фикстуры: они молча приносят старый контракт.

## Шаг 2 — намерение сторон

По каждому конфликту прочитай коммиты обеих сторон (`git show <sha>`) и пойми, что и зачем меняли.

Тривиальный на вид хунк (отступ, переименование, пара строк) проверяй так же: логический конфликт — собирается, но поведение сломано — опаснее текстового и част в rebase/cherry-pick. Смотри, как изменённый символ используется рядом.

## Шаг 3 — решать самому или спрашивать

**Сам**, если намерение выводится из коммитов: одна сторона трогала код, другая нет → берёшь ту, что меняла; изменения ортогональны → объединяешь.

**Спрашивай**, если обе стороны меняли одну логику. Вопрос — готовый выбор с последствиями, а не «как разрулить»:

> «`useRecaptcha`: в stash `showRecaptchaBadge()` на маунте, в ветке — лениво по фокусу. Взять ленивую из ветки, оставить eager из stash, или объединить?»

## Шаг 4 — единый план

Один план по всем конфликтам сразу, не по файлу за раз:

```markdown
## Context
<что разошлось между сторонами — 2-4 строки>

## Разрешения
- **<файл>** → берём <сторону/комбинацию>; отбрасываем <что>; потому что <причина из коммитов>.

## Пограничные случаи
- <undefined-символы, дубли импортов, переполнение>

## Верификация
- <чем проверим — Шаг 6>
```

`ExitPlanMode` на аппрув. Правки — только после одобрения.

## Шаг 5 — применить

Правь файлы, удали **все** маркеры: `<<<<<<<`, `|||||||`, `=======`, `>>>>>>>`.

## Шаг 6 — верификация

1. **Маркеры вычищены** — оба вывода пусты:
   ```bash
   git diff --check
   grep -nE '^(<<<<<<<|=======|>>>>>>>|\|\|\|\|\|\|\|)( |$)' <изменённые файлы>
   ```
2. **Структурная сверка ещё раз** — `python3 <skill_dir>/scripts/check_merge_symbols.py`: резолв сам мог уронить символ или оставить дубль.
3. **Нет битых ссылок** — не взял вызов одной стороны без реализации другой: undefined-переменные, потерянные импорты. Главная ошибка после резолва.
4. **Lint / type-check** — бинарём напрямую (`npx tsc --noEmit`, `npx eslint`), не через turbo/`pnpm`-таску: та тянет build.
5. **Затронутые тесты прогони сам** (`jest <dir>`, `playwright test --grep`), а не только конфликтный файл.

Не сошлось — вернись к плану и скажи, не замалчивай.

**Вывод хуков — не задание.** Что печатают `Stop`/`PostToolUse`-хуки (eslint, stylelint, tsc, prettier), приходит мимо плана: не правь по нему код и не расширяй резолв. Задело конфликтные файлы — строка в отчёте; остальное — по явной просьбе.

## Особый режим — восстановление потерянного патча

Пользователь даёт коммит-источник («потеряли правки после мержа, вот `b148d1dd`»):

1. `git show <sha>` — что коммит менял.
2. Сравнить с текущим состоянием — что пропало при слиянии.
3. Переприменить **точечно** потерянный хунк правкой файла, а не `cherry-pick` всего коммита: иначе вернёшь и то, что уже на месте.
4. Верификация — Шаг 6.
