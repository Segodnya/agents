# Сводка по диффу для MR

Собери дифф по выбранному скоупу и выдай **готовую к вставке в описание MR** сводку:
короткие однострочные пункты, по одному на логическое изменение.

## Скоуп

Аргумент: `$ARGUMENTS` (по умолчанию — `staged`).

- (пусто) / `staged` → `git diff --staged`
- `branch` → от точки ответвления с master:
  `BASE=$(git merge-base origin/master HEAD 2>/dev/null || git merge-base master HEAD 2>/dev/null || echo HEAD)`,
  затем `git diff "$BASE"` (коммиты ветки + незакоммиченное — то, что уходит в MR).
- `working` / `head` → `git diff HEAD`
- иначе трактуй аргумент как git-ref / range и сделай `git diff <arg>`.

Сначала `git diff --stat <scope>` для карты файлов, затем сам дифф для содержания.
Если дифф пустой — ответь одной строкой «Нет изменений в выбранном скоупе» и остановись.
Бинарные / lock / сгенерированные / минифицированные файлы в содержание не разбирай —
упомяни одной строкой, только если это важно.

## Формат вывода

Только markdown-список (`-`), без преамбул, заголовков и финальных выводов — чтобы можно было
скопировать целиком в описание MR.

Правила:

1. Одна строка = одно **логическое** изменение, а не «изменён файл X». Описывай суть и зачем.
2. Связанные правки в нескольких файлах — в один пункт (переезд / переименование / рефактор разом).
3. Порядок — от главного к второстепенному.
4. Лаконично; маркеры (новый / удалён / переименован) — только когда это и есть суть пункта.
5. Не домысливай мотив: если из диффа цель неочевидна — описывай наблюдаемое изменение, без догадок.
6. Без «возможно» / «кажется» — пиши по факту диффа.

Только чтение: не делай `git add` / `git commit`, не запускай сборку.
