# agents

Личные скиллы и команды для Claude Code.

## Скиллы

Скиллы с пометкой «только вручную» запускаются только слэш-командой: модель сама их не вызывает (`disable-model-invocation`).

### MR и ревью

| Скилл | Что делает |
|---|---|
| [`mr-ready`](skills/mr-ready) | Доводит MR до состояния, когда его можно мержить. В каждом раунде `review-staged` ищет проблемы, `audit-reply --auto --commit` правит или отвечает, коммиты остаются локальными. Раунды повторяются, пока ревью не станет чистым, пока несколько раундов подряд не найдут только мелочи (P2) или пока не пройдёт 10 раундов. Ссылки Figma из вызова или ТЗ скилл снимает в скриншоты, и ревьюер сверяет с ними вёрстку. Состояние лежит в `state.json` внутри `.git` и переживает перезапуск. GitLab скилл читает один раз на старте, а пишет один раз в конце: один push, ответы в треды людей, треды только для того, что нужно ревьюеру-человеку, и описание MR по шаблону `pr` от Matt Pocock (Summary, Merge Danger, «Требует внимания»). Пользователя спрашивает только о продуктовых развилках, одним вопросом перед push. Чек-лист отгрузки скилл обновляет сам, а комментарий в Jira меняется только после подтверждения. Из всех скиллов коммитит и пушит только этот. |
| [`review-staged`](skills/review-staged) | Ищет в диффе (staged / last / branch / worktree) как можно больше проблем, а в отчёт пускает только доказанные. Четыре ревьюера идут по своим осям: корректность и контракты, правила и запахи, производительность, чек-лист отгрузки. На каждый дефект они ищут такие же места. Гейт `_lib/gate.py` (общий с `bugty-hunter`) сверяет цитату каждой находки с реальным файлом и отбрасывает находки без совпадения. Снятое в тредах МР помечается, дефекты старше диффа уходят черновиками тикетов. Флаги (`--no-mr`, `--no-spec`, `--base`, `--checklist`, `--checks` …) заранее отвечают на вопросы настройки, чтобы скилл работал без человека. Код не трогает, пишет только отчёт. |
| [`review-with-matt`](skills/review-with-matt) | Только вручную. Обёртка над `/mattpocock-skills:code-review`. Берёт спеку из Jira, сверяет находки с тредами MR (принято / отклонено / открыто) и публикует подтверждённые: новым тредом или ответом в существующий. |
| [`audit-reply`](skills/audit-reply) | Разбирает замечания ревьюера из тредов GitLab MR, отчёта или текста. На каждое готовит правку или ответ с обоснованием. Правка закрывает замечание целиком и без побочных эффектов: все экземпляры паттерна, вызывающие, парная операция, тест с независимым эталоном. Учитывает решения из `### Settled`. Работает интерактивно или под `--auto` для `mr-ready`. |
| [`merge-resolve`](skills/merge-resolve) | Разрешает конфликты git (merge / rebase / cherry-pick / stash) по единому плану и возвращает правки, потерянные после мержа. |

### Баги

| Скилл | Что делает |
|---|---|
| [`bugty-hunter`](skills/bugty-hunter) | Ищет баги в одном из трёх скоупов: дифф, модуль (фича, флоу) или проект (3–5 зон на выбор). Агент разведки строит карту периметра. Затем три агента ищут по осям: состояние и асинхрон, жизненный цикл и утечки памяти, контракты и крайние данные. У каждого бага есть дословная цитата, путь от входной точки, шаги воспроизведения и черновик тикета. Находки, путь к которым проследить не удалось, попадают в «подозрения» без тикета. Код не трогает. |
| [`bug-flow`](skills/bug-flow) | Ведёт баг-тикет Jira: воспроизведение на стенде, комментарий с кейсом, минимальный фикс, комментарий «причина / решение / риски». Wiki-разметку отправляет через REST (`scripts/jira_put.py`). |
| [`local-debug`](skills/local-debug) | Расставляет пробы `console.warn` и по логам находит причину бага. Если баг воспроизводится только на билде, даёт сниппеты для консоли прод-сборки. |

### Документы и дизайн

| Скилл | Что делает |
|---|---|
| [`tech-task`](skills/tech-task) | Пишет низкоуровневое ТЗ для фронтенд-задачи: постановка, use cases, варианты реализации, план отгрузки, метрики, декомпозиция. |
| [`review-docs`](skills/review-docs) | Сверяет готовый документ (ТЗ, дизайн, ресёрч, план) с кодом репозиториев, которые в нём упомянуты. Документ делится на шарды по секциям, каждое утверждение подкрепляется дословной цитатой из файла, механический гейт отсекает неподтверждённое. Ищет неточности, противоречия, слепые пятна и открытые вопросы к автору. |
| [`audit-dsgn`](skills/audit-dsgn) | Проверяет макет Figma против кода. Разведка кода и чтение макета идут параллельно, макет сверяется с чек-листом аудита. В итоге остаются только дельта-вопросы дизайнеру или продакту: в скоупе тикета, не решённые поведением соседней фичи и требующие решения человека. По просьбе публикует вопросы закреплёнными комментариями в Figma (`scripts/post_comments.py`). |

### Работа с Claude Code и командой

| Скилл | Что делает |
|---|---|
| [`dev-feedback`](skills/dev-feedback) | Готовит фидбэк на разработчика по его МР в GitLab за период. Собирает merged, closed и открытые МР с активностью, разбирает диффы и треды субагентами, считает скорость реакции на ревью. |
| [`perf-review`](skills/perf-review) | Только вручную. Жёсткое, без комплиментов, performance-ревью работы с Claude Code за N дней. |
| [`memory-audit`](skills/memory-audit) | Только вручную. Проверяет файловую память Claude Code по проекту. Каждая запись сверяется с кодом, правилами и скиллами и получает вердикт «оставить / исправить / слить / удалить». Вердикты применяются после подтверждения. `scripts/memory.py` собирает инвентарь и пересобирает индекс. |
| [`chore-agent-cli`](skills/chore-agent-cli) | Только вручную. Находит в транскриптах команды, которые агент повторяет руками, и превращает их в подкоманды `agent-cli` и правила мода `agent-cli-first`. Работает в двух слоях. Слой `user` (`~/.claude`) читает все проекты и собирает общие команды: git-состояние, трекеры, CI. Слой `project` (`<repo>`) читает только текущий репо и собирает его проверки и скрипты. `scan.ts` (bun) считает повторы по сессиям и проектам и пропускает то, что моды уже перенаправляют. Каждый сигнал получает вердикт и слой. Если CLI в слое ещё нет, скилл собирает первую версию из скана. Правки вносит после подтверждения. |

## Запуск `mr-ready`

Запускай в сессии Claude Code в целевом репозитории, на ветке MR, в auto-режиме разрешений. Нужен
`glab` с авторизацией на хосте и бинарники проверок в репо (`tsc`, `eslint`, `jest` …), а для сверки с
макетом — подключённый Figma MCP:

```text
/segodnya-agents:mr-ready Чек-лист отгрузки: https://jira.example.com/browse/KEY-1?focusedCommentId=123
```

| Команда | Что делает |
|---|---|

## Установка

Этот репозиторий одновременно и плагин Claude Code `segodnya-agents`, и маркетплейс, из которого он
ставится. Ставить можно только целиком: скиллы вызывают скрипты друг друга (`SKILL_DIR/../audit-reply/…`,
`SKILL_DIR/../mr-ready/…`) и общий код из `skills/_lib/` (`glab_mr`, `run`, `jira`, `gate`). Отдельный
скилл без соседей не запустится.

```
/plugin marketplace add Segodnya/agents
/plugin install segodnya-agents@segodnya-agents
```

Скиллы и команды получают префикс плагина: `/segodnya-agents:mr-ready`,
`Skill segodnya-agents:review-staged`. Новые коммиты приходят по `/plugin marketplace update
segodnya-agents` или автоматически, если включить auto-update для маркетплейса в `/plugin` →
Marketplaces. В `plugin.json` намеренно нет `version`: с ним обновления приходили бы только при смене
версии.

## Локальная разработка

Подключи чекаут как локальный маркетплейс. Тогда Claude Code читает файлы прямо из него и не копирует
их в кэш:

```bash
claude plugin marketplace add ~/path/to/agents
claude plugin install segodnya-agents@segodnya-agents
```

- Правка подхватывается в новой сессии или по `/reload-plugins` в текущей. Поднимать `version` не нужно.
- Ветку или worktree на одну сессию подключает `claude --plugin-dir ~/path/to/worktree`.
- Перед проверкой запусти `claude plugin validate .`: он проверяет манифесты и пути.
- Удали старые симлинки скиллов из `~/.claude/skills` (и из `~/.agents/skills`, если ставил через
  skills.sh). Иначе каждый скилл загрузится дважды: без префикса и с префиксом.
